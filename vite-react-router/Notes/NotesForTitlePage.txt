## Title Page - Implementation Notes
### Last Updated: December 15, 2025

### Overview:
- Refactored Title page (src/pages/Title.jsx) using custom hook architecture
- Uses useTitleData hook for data management, MainDisplay for layout
- **TMDB Integration**: Uses TMDB API for posters, cast photos, and similar titles
- Route: /title/:titleId
- Backend: https://localhost:5001 | Frontend: http://localhost:5173

### Page Sections:
1. **Header** (MainDisplay): Poster (TMDB) + title, year, rating, bookmark, badges (mediaType, runtime), sections (genres, overview)
2. **Top Cast**: Grid with 4 featured cast members (circular photos from TMDB)
3. **Full Cast**: Simple list with all cast members (photos from TMDB, clickable rows)
4. **Similar Titles**: Carousel with poster cards and bookmark buttons (backend first, TMDB fallback)
5. **Reviews**: User's own review (editable UserCard) + all reviews (read-only UserCards)

### Key Features:
- **TMDB Posters**: Fetches high-quality movie/show posters when backend doesn't provide
- **TMDB Cast Photos**: Parallel fetch for all cast member profile pictures
- **TMDB Similar Titles**: Backend API tried first, TMDB used as fallback
- **Similar Title Bookmarks**: Can bookmark similar titles directly from carousel
- **Cast List Design**: Simple clickable rows with hover effects (matching Individual filmography)
- **Responsive Carousel**: Similar titles in carousel with bookmark overlay buttons

### API Integration (src/business-logic-layer/ApiClient/ApiClient.jsx):

**Working Endpoints:**

- mdb.apiv2.titles.getRatings(id) - Reviews/ratings
- mdb.apiv2.titles.getSimilar(id) - Similar titles (may not include posters)
- mdb.apiv2.user.getBookmark(userId, titleId) - Check bookmark status

### Architecture:

**Title.jsx Structure:**
- Uses useTitleData hook (returns 14 values)
- Local state for user review text, TMDB data, and bookmark states
- useEffect hooks for TMDB poster, cast photos, similar titles, and bookmarks
- Conditional rendering: loading → error → no title → success
- Prepares badges and sections arrays before rendering
- MainDisplay with five Container sections (Top Cast, Full Cast, Similar Titles, Reviews)
- Custom carousel render function for similar titles with bookmarks

**useTitleData Hook:**
- 10 state variables: title, loading, error, cast, loadingCast, reviews, loadingReviews, isBookmarked, userRating, loadingUserRating
- 5 useEffect hooks (title, cast, reviews, bookmark status, user rating)
- 3 handler functions (toggleBookmark, updateUserRating, deleteUserRating)
- All backend data fetching centralized in hook
- Returns all state and handlers to Title component

**TMDB Integration in Title.jsx:**
1. **Title Poster** (useEffect):
   - Runs when title data loads
   - Calls tmdb.getTitlePoster(title.name, title.mediaType, title.startYear)
   - Fallback to Image-not-found.png if TMDB fails

2. **Cast Photos** (useEffect):
   - Runs when cast data loads
   - Extracts actor names into array
   - Calls tmdb.getMultiplePersonPhotos(actorNames)
   - Returns object keyed by name: { "Tom Hanks": "url...", ... }
   - Parallel fetch for performance

3. **Similar Titles** (useEffect):
   - Tries backend API first: mdb.apiv2.titles.getSimilar(titleId)
   - Falls back to TMDB if backend returns empty or errors
   - Calls tmdb.getSimilarTitles() for fallback
   - Provides complete data (name, poster, year, mediaType)

4. **Similar Title Posters** (useEffect):
   - Runs when similar titles load
   - Checks if each title already has poster
   - Fetches missing posters from TMDB
   - Parallel fetch using Promise.all()
   - Stores in similarPosters state object

**Bookmark Functionality:**
- Main title bookmark in MainDisplay header
- Similar title bookmarks in carousel (ToggleButton overlay)
- handleSimilarTitleBookmark() toggles bookmark for each similar title
- Calls mdb.apiv2.user.addBookmark() or removeBookmark()
- Updates similarBookmarks state for responsive UI

#### Why Relationship Endpoints Matter:

**Performance:**
- Single JOIN query returns only needed data (KB instead of MB)
- No need to fetch entire database and filter client-side
- Faster load times and better user experience

**Data Quality:**
- Includes relationship metadata (character names, billing order, categories)
- Provides properly structured data for UI components
- Enables pagination, filtering, and sorting

**REST Best Practices:**
- Separate endpoints for entities vs relationships
- Clear, predictable API structure
- Follows industry standards (TMDB, Spotify, GitHub patterns)

**Example Query Pattern:**
```sql
SELECT i.id, i.name, i.profilePath, tp.character, tp.order
FROM title_principals tp
JOIN individuals i ON tp.individualId = i.id
WHERE tp.titleId = :titleId
ORDER BY tp.order LIMIT 10
```

### Design Patterns Used:
- Custom hooks for data management (useTitleData)
- Component composition (MainDisplay, MediaCard, UserCard, GridListComp)
- Separation of concerns (UI vs data fetching)

- Props drilling minimized through hook pattern
