## Individual Page - Implementation Notes

### Overview:
- Created Individual page (src/pages/Individual.jsx) for displaying actor/person details
- Uses custom hook architecture with useIndividualData hook
- Reuses MainDisplay component for consistent layout with Title page
- Route: /individual/:individualId
- Backend: https://localhost:5001 | Frontend: http://localhost:5173

### Page Sections:
1. **Header** (MainDisplay): Profile picture + name, job badges, lifespan (born-died), biography, "Add to List" button
2. **Awards & Nominations**: Placeholder section (API endpoint not available yet)
3. **Photo Gallery**: Placeholder section (API endpoint not available yet)
4. **Known For**: GridListComp with MediaCard components showing titles grouped by profession (Actor, Director, Producer, etc.)

### Key Features:
- **"Add to List" Button**: Replaced rating/rate button with custom action to add individual to user lists
- **ListManager Component**: Reusable modal for managing lists (create new list or add to existing)
- **No Bookmark**: Bookmark functionality removed (only used on Title pages for movies/shows)
- **Profession Badges**: Shows "Actor" badge by default (awaiting profession data from API)
- **Known For Grouping**: Framework ready to group titles by profession when API provides data

### API Integration (src/business-logic-layer/ApiClient/ApiClient.jsx):

**Working Endpoints:**
- mdb.apiv2.individuals.getById(id) - Main individual data (name, birth/death year, image, rating)
- mdb.apiv2.individuals.getTitles(id) - Titles person is known for (movies/shows they appeared in)

**Missing/Placeholder Data:**
- Biography/description field (showing placeholder text)
- Awards/nominations endpoint
- Photo gallery endpoint (multiple images)
- Profession data for accurate job badges
- Character/role information in Known For titles

**Key Data Mapping:**
- individual.name → Title in MainDisplay
- individual.image → Profile picture
- individual.birthYear/deathYear → Lifespan section
- individual.rating → Not displayed (replaced with "Add to List" button)
- knownForTitles[] → MediaCard grid in Known For section

- **src/pages/Individual.jsx** (245 lines) - Main page component

### Architecture:

**Individual.jsx Structure:**
- Uses useIndividualData hook (returns 8 values)
- Local state for ListManager modal (showListModal)
- Conditional rendering: loading → error → no individual → success
- Prepares badges and sections arrays before rendering
- MainDisplay with customAction prop for "Add to List" button
- Three Container sections (Awards, Photos, Known For)
- ListManager component for list operations

**useIndividualData Hook:**
- 6 state variables: individual, loading, error, knownForTitles, loadingKnownFor
- 2 useEffect hooks (individual basic data, known for titles)
- All data fetching and API calls centralized in hook
- Returns all state to Individual component
- Note: Bookmark-related states removed (isBookmarked, loadingBookmark, toggleBookmark)

**ListManager Component:**
- Reusable modal for adding items to user lists
- Supports both individuals and titles (itemType prop)
- Features: Select existing list, create new list, form validation
- Loading states and error handling
- Success/error callbacks to parent component
- Currently uses dummy list data (ready for API integration)

### MainDisplay Enhancement:
**Added customAction prop** to support flexible action buttons:
```jsx
customAction={{
    label: 'Add to List',
    variant: 'primary',
    icon: '📋',
    onClick: handleAddToList
}}
```

**Priority Order:**
1. If customAction provided → Shows custom button
2. Else if rating provided → Shows rating display + "Rate" button
3. Else → Shows "★ Rate" button

This makes MainDisplay more versatile for different page types!
